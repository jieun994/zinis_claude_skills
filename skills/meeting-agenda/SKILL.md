Use this skill whenever the user is heading into a meeting and needs to know what to ask or decide, even if they never say "아젠다".

# 회의 아젠다 준비 (meeting-agenda)

> 회의 **전에** 안건·물어볼 것·결정할 것을 뽑아준다. 회의록(meeting-minutes)의 짝이 되는 앞단 스킬이다.

사용자는 비개발자일 수 있고, 회의 10분 전에 급하게 이 스킬을 여는 경우가 많다. 질문은 최소한으로, 결과는 회의 자리에서 바로 보고 체크할 수 있는 형태로 낸다.

## 이 스킬의 철칙 (Iron Law)

**근거가 없는 안건은 안건으로 쓰지 않는다.**

이 스킬은 meeting-minutes와 달리 근거가 되는 원문(녹취록)이 없는 상태에서 시작하는 경우가 정상이다. 그래서 빈칸을 그럴듯한 일반론으로 채우려는 압력이 구조적으로 크다. 하지만 `1. 진행 현황 공유 2. 이슈 논의 3. 다음 일정 협의` 같은 결과물은 사용자가 이미 알고 있는 내용이라 아무 도움이 안 되고, 한 번 겪으면 다시는 이 스킬을 열지 않는다.

근거를 못 찾은 항목은 안건 목록에서 빼거나, `가정 — 확인 필요`로 따로 표시한다. 확정 안건인 척 섞지 않는다.

**합리화 차단표 — 아래 생각이 떠오르면 철칙을 어기는 중이다:**

| 떠오르는 생각 | 실제 |
|---|---|
| "자료가 없으니 일반적인 안건이라도 채워주자" | 일반 안건은 사용자가 이미 안다. 채우는 게 아니라 "자료를 주면 구체화된다"고 알리는 게 도움이다 |
| "웹 프로젝트면 보통 이런 이슈가 있으니 넣어두자" | 이 프로젝트에 그 이슈가 있다는 근거가 없다. 없는 이슈를 회의 자리에서 꺼내면 사용자가 곤란해진다 |
| "안건이 3개뿐이라 좀 빈약해 보이는데 몇 개 더" | 근거 있는 안건 3개가 근거 없는 안건 10개보다 낫다. 개수를 목표로 삼지 않는다 |
| "담당자/기한을 비워두면 어설퍼 보이니 추정해서 쓰자" | 틀린 기한을 회의에서 말하면 사용자 신뢰가 깨진다. `미정(확인 필요)`이 정답이다 |
| "사용자가 급하다니까 자가검증은 건너뛰자" | 급할수록 훑어보지 않고 그대로 쓴다. 급할 때가 검증이 제일 중요하다 |

**Red Flags — 다음이 보이면 멈추고 되돌린다:**
- 안건 문구에 이 프로젝트의 고유명사(화면명·기능명·회사명·인명·날짜·문서명)가 하나도 없다
- 다른 프로젝트에 그대로 복사해도 말이 되는 안건이다
- "물어볼 것"이 "일정은 어떻게 되나요?" 수준의 형식적 질문이다
- 근거 표기 `(근거: …)`가 비어 있는데 확정 안건 목록에 들어가 있다
- 결과물이 `[체크리스트 제안]`으로만 가득 차 있다 — 개수로 빈약함을 감추려는 중이다

**Spirit vs Letter**: 근거 표기를 형식적으로 붙이는 게 목적이 아니다. 목적은 "회의에서 이걸 왜 물어봐야 하는지 사용자가 자기 입으로 설명할 수 있게" 만드는 것이다. 근거를 붙였는데도 사용자가 그 안건의 이유를 설명 못 하면 그 안건은 실패한 안건이다.

## 워크플로우

### Step 1: 회의 맥락 파악
**타입**: prompt

첨부 자료 유무와 관계없이 최소 정보를 먼저 확보한다. 한 번에 다 묻지 말고 필요한 것만 묻는다.

**반드시 필요한 것 (없으면 진행 불가):**
- 회의 목적 한 줄 — "A사에 화면설계 확인받기", "결제 연동 방식 정하기" 수준이면 충분

**있으면 품질이 크게 오르는 것 (없어도 진행):**

| 자료 | 역할 |
|---|---|
| 직전 회의록 (.xlsx/.docx/텍스트) | 미완료 TO-DO·미해결 이슈 승계 — 이 스킬의 핵심 가치 |
| 흩어진 메모 | 사용자가 신경 쓰고 있는 지점 |
| 기획 산출물 (IA·요구사항·화면설계) | `미정`·`TBD`·`검토중` 표시가 곧 물어볼 것 |

**긴급 모드 판단**: 사용자 말투에 "지금", "곧", "10분 뒤", "이따 바로" 같은 신호가 있으면 추가 질문 없이 가진 정보만으로 바로 초안을 낸다. **회의 목적조차 없어도 묻지 않는다** — 긴급 신호는 아래 '실패 처리'의 목적 확인 질문보다 우선한다. 부족한 부분은 결과물에 `확인 필요`로 표시하고, 마지막에 "자료를 주시면 구체화해드릴게요"라고 한 줄 덧붙인다. 급한 사람에게 질문을 던지는 것이 이 스킬의 가장 큰 실패다.

**과거 녹취록 + 다가올 회의가 섞였을 때**: "클로바노트 있는데 내일 회의 대비해서 정리해줘"처럼 끝난 회의의 원본 기록과 다가올 회의 준비가 한 문장에 있으면, 판단하지 말고 한 문장으로 되묻는다 — "이 녹취를 회의록으로 먼저 정리할까요, 아니면 내일 회의 아젠다부터 뽑을까요?" 녹취록은 meeting-minutes의 입력이고 이 스킬의 입력은 정리된 회의록이라, 잘못 고르면 사용자가 원한 산출물이 안 나온다. 이 되묻기는 긴급 모드에서도 생략하지 않는다 — 산출물 종류 자체가 갈리기 때문이다.

**회의 유형은 묻지 않고 추론한다**: 회의 목적 한 줄과 자료에서 킥오프 / 정기 점검 / 이슈 해결·의사결정 / 산출물 검수·보고 / 오픈 전 점검 / 개발·디자인 협의 중 하나로 판단한다. 결과물 상단에 어떤 유형으로 봤는지 한 줄 밝힌다.

판단 근거가 전혀 없으면 유형을 찍지 말고 **미정으로 둔다**. 이때는 특정 유형을 전제하는 항목(예: "지난 회의 TO-DO 완료 여부" — 이전 회의가 있었다는 전제, "오픈 판단 기준" — 오픈이 임박했다는 전제)을 쓰지 않는다. 첫 미팅인데 "지난 회의 TO-DO 확인하세요"가 적혀 있으면 사용자가 회의 자리에서 어색해진다. 유형 미정일 때는 어느 회의에서나 전제가 성립하는 항목만 고른다.

### Step 2: 이월 항목 승계
**타입**: script

직전 회의록이 있으면 여기서 이 스킬의 값어치가 나온다. meeting-minutes 표준 양식 엑셀은 Claude가 직접 읽을 수 없으므로 스크립트를 거친다:

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/read_minutes.py" "지난회의록.xlsx"
```

(Windows PowerShell에서는 `$env:CLAUDE_PLUGIN_ROOT`, `python3`이 없으면 `python`.)

스크립트는 회의 개요·회의 내용·TO-DO·이슈를 JSON으로 뽑고, **미완료 TO-DO**(완료일이 비어 있음)와 **미해결 이슈**(현황이 완료·종료가 아님), **`미정(확인 필요)` 표기가 남은 항목**을 `carryover`에 따로 모아준다. 이 세 묶음이 이번 회의 안건의 1순위 후보다.

엑셀이 아닌 형식(.docx, 텍스트, 붙여넣은 내용)이면 스크립트 없이 직접 읽되 같은 기준으로 추린다.

**자료 정합성 확인**: 회의록의 프로젝트명·날짜가 이번 회의와 맞는지 대조한다. 다른 프로젝트 것이거나 날짜가 한참 이전이면 진행 전에 "이 회의록이 이번 회의 건이 맞나요?"라고 되묻는다. 자료끼리 모순되면(회의록엔 "A로 결정", 메모엔 "B로 재논의") 임의로 고르지 말고 어느 쪽이 최신인지 사용자에게 묻는다.

산출물(IA·요구사항 엑셀 등)이 왔으면 `미정`·`TBD`·`보류`·`검토중` 표시가 있는 행을 추출한다. 표준 양식이 아닌 사용자 자체 제작 엑셀은 컬럼 의미를 추측하지 말고 구조를 먼저 확인한다.

### Step 3: 체크리스트 대조
**타입**: rag

`references/agenda-checklist.md`를 읽고 추론한 회의 유형의 표와 대조한다. 여기서 나오는 것은 절차성 누락(의사결정권자 참석 여부, 다음 마일스톤 확인 등)을 잡기 위한 **보완**이지 안건의 본체가 아니다.

체크리스트에서 온 항목은 반드시 `[체크리스트 제안]`으로 표시해서, 자료 근거로 나온 항목과 시각적으로 구분한다. 입력이 빈약할수록 이 표시가 많아지고, 그 자체가 사용자에게 "자료를 주면 좋아진다"는 신호가 된다.

**개수 상한 — 체크리스트 항목은 자료 근거 안건보다 많을 수 없다.** 자료 근거 안건이 3개면 체크리스트는 최대 3개다. 자료가 아예 없어 **근거 안건이 0개면 체크리스트 항목도 최대 2개만** 고른다. 이 회의 성격상 가장 놓치기 쉬운 것 위주로 고르고, 표에 있다고 다 옮기지 않는다.

**세는 단위는 출력에 찍히는 줄이다.** 안건 / 물어볼 것 / 결정할 것 세 섹션을 **합산**해서 센다. 체크리스트 표의 한 행을 세 섹션에 쪼개 넣으면 3줄이므로 3개로 센다 — 한 행이니 1개라고 세면 상한을 우회하는 것이다.

체크리스트 5~6개를 그대로 나열한 결과물은 "속 빈 리스트"다 — 사용자가 이미 아는 내용을 개수로 채운 것이라 도움이 안 되고, 오히려 "이 스킬은 뻔한 소리를 한다"는 인상만 남긴다. 자료가 없을 때 이 스킬이 할 일은 안건을 채우는 게 아니라 **적게 주고 왜 적은지 밝히는 것**이다.

### Step 4: 자가검증
**타입**: review

초안을 사용자에게 보여주기 **전에** 스스로 검사한다. 두 가지를 모두 수행한다.

1. **일반론 검사** — 안건 한 줄씩 훑으며 이 프로젝트의 고유명사가 하나도 없는 항목을 찾는다. 찾으면 구체화하거나 삭제한다. `[체크리스트 제안]` 항목은 고유명사 요건에서 예외지만 **개수 상한(Step 3)에서는 예외가 아니다** — 상한을 넘겼으면 넘긴 만큼 지운다. 회사명만 바꿔 다른 프로젝트에 그대로 붙여도 말이 되는 항목이 결과물의 절반을 넘으면 개수를 줄인다.
   - 나쁜 예: `2. 진행 현황 공유`
   - 좋은 예: `2. [화면설계] 마이페이지 결제내역 화면 — 7/20 회의 보류 항목 재확인 (근거: 7/20 회의록 TO-DO#3, 완료일 공란)`
2. **근거 대조** — 각 안건의 `(근거: …)`가 실제로 입력 자료에 있는지 되짚는다. 기억으로 쓴 근거는 근거가 아니다. 확인 안 되면 `가정 — 확인 필요`로 내린다.

검증 후 마크다운 초안을 대화창에 보여주고 "이 중 사실과 다르거나 불필요한 안건이 있으면 빼주세요"라고 확인받는다. 긴급 모드에서는 확인을 기다리지 말고 초안을 그대로 주되, 검증 자체는 생략하지 않는다.

### Step 5: 결과물 전달
**타입**: generate

화면에 바로 마크다운 체크리스트로 출력한다. 회의 자리에서 노트북으로 보며 체크하는 용도이므로 파일 저장은 기본이 아니다.

**출력 구조 3분류:**

```markdown
## [프로젝트명] {회의명} 아젠다 — {날짜}
회의 유형: {추론한 유형} · 목적: {한 줄}

### 안건 (다룰 것)
- [ ] 1. {안건} (근거: {출처})
- [ ] 2. **[체크리스트 제안]** {안건}   ← 체크리스트에서 온 항목은 문두에 태그

### 물어볼 것 (확인 필요)
- [ ] {질문} — 왜 물어야 하는지 한 줄 (근거: {출처})

### 결정할 것 (오늘 못 정하면 일정에 영향)
- [ ] {결정 사항} / 선택지: {A} vs {B} (근거: {출처})
  못 정하면: {일정·후속 작업에 생기는 일}

### 가정 — 확인 필요
- {근거를 못 찾았지만 짚어볼 만한 것}
```

**"물어볼 것"·"결정할 것" 도출 규칙**: 자료에 `미정`·`TBD`·`보류`·`내부 논의`·`검토하겠다`·`다르게 이해` 같은 신호가 있는 항목에서만 뽑는다. 신호가 없는데 질문을 만들어내면 지어낸 것이다.

**입력이 빈약했으면 먼저 고지한다**: "자료가 없어서 일반적인 안건 위주로 구성했어요. 지난 회의록이나 메모를 주시면 훨씬 구체화됩니다." 뻔한 결과를 뻔하다고 스스로 밝히는 것이 신뢰를 지킨다.

**선택 옵션 (사용자가 요청할 때만):**
- `.md` 파일로 저장
- **공유용 정제본** — 상대방에게 미리 보낼 아젠다. "물어볼 것"의 속내(우려·협상 포인트)와 `가정 — 확인 필요` 섹션을 빼고 안건·결정 사항만 정중한 문장으로 다듬는다. 본인용과 공유용은 성격이 다르므로 섞지 않는다.

## 실패 처리

- 스크립트 실행이나 파일 읽기가 실패해도 그때까지 정리된 초안은 **즉시 대화창에 출력한다**. 회의가 임박한 상황이 대부분이라 재시도할 시간이 없다.
- 파일이 손상·암호화·이미지 스캔이라 읽을 수 없으면 시작 전에 알리고 "메모로 대체할지, 다른 파일을 줄지" 확인한다. 조용히 건너뛰지 않는다.
- 회의 목적조차 없으면 딱 한 가지만 묻는다: "이번 회의에서 뭘 얻어야 하나요?" 그 외의 정보는 없는 채로 진행한다. **단 긴급 신호가 있으면 이 질문도 생략하고 바로 초안을 낸다** — 급할 때는 질문 하나가 부담이고, 목적은 결과물 상단에 `목적: 확인 필요`로 표시하면 된다.

## 회의 후

결과물 전달 후 한 줄로 안내한다: "회의 끝나고 녹취록 주시면 `meeting-minutes`로 회의록 만들어드릴게요." 두 스킬이 이어지는 흐름을 사용자가 알게 한다.

## References

- **`references/agenda-checklist.md`** — 회의 유형별(킥오프/정기점검/이슈해결/검수보고/오픈전/개발협의) 기본 안건 · 자주 놓치는 질문 · 결정 필요 신호. Step 3에서 읽는다.

## Scripts

- **`scripts/read_minutes.py`** — meeting-minutes 표준 양식 회의록(.xlsx) → JSON. 미완료 TO-DO·미해결 이슈·미정 항목을 `carryover`로 따로 추출한다.

## Settings

| 설정 | 기본값 | 변경 방법 |
|------|--------|-----------|
| 출력 형태 | 대화창 마크다운 체크리스트 | "파일로 저장해줘" → `.md` 저장 |

| 긴급 모드 | 급한 신호가 있으면 자동 | "천천히 물어봐도 돼" → 일반 모드 |
